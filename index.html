TDD & AI Research June 2025 • 6 min read

Exploring Test-Driven Development with AI Prompt Engineering

Key insights from our BTH degree thesis investigating how structured prompt engineering can make Test-Driven Development more accessible and effective.

Collapse Article ▲

Background & Motivation

Test-Driven Development (TDD) is renowned for yielding clean, modular, and maintainable software. Yet in practice, developers—especially those early in their careers—often struggle with the discipline of writing concise tests before writing production code.

In our thesis research at Blekinge Institute of Technology (BTH), we explored how generative AI and structured prompt engineering can act as a catalyst for TDD adoption.

The Role of Prompt Engineering in TDD

Rather than asking an LLM to generate entire codebases end-to-end, our research found that the most effective AI collaboration happens at the unit test boundary:

  • Specification Decomposition: Formulating user requirements into small, testable behavior specifications.
  • Edge-Case Brainstorming: Prompting the model to challenge assumptions and identify boundary edge cases before implementation.
  • Test-First Scaffolding: Generating isolated, mock-free test assertions that define the expected contract.
// Example of AI-assisted test-first boundary specification
describe('PipelineHealthMonitor', () => {
  it('should trigger alert when failure rate exceeds threshold over 5m window', () => {
    const monitor = new PipelineHealthMonitor({ failureThreshold: 0.1 });
    const status = monitor.evaluateEvents(mockPipelineEvents);
    expect(status.alertTriggered).toBe(true);
  });
});

Key Findings

Structured prompts with explicit input/output contracts dramatically reduce hallucinations. Developers practicing TDD with prompt-assisted test scaffolding reported higher confidence and better test coverage.

Pipeline Observability: Automated Health & Alerting with OpenTelemetry

Why internal delivery pipelines deserve first-class telemetry, distributed tracing, and automated failure detection.

Read Full Article ▼

The Hidden Cost of Opaque Pipelines

Modern software delivery relies heavily on complex CI/CD environments with multi-stage build matrices, test executions, and automated deployments. Yet when a pipeline fails or slows down, developers often spend hours digging through thousands of lines of unformatted console logs.

Treating CI/CD as a Distributed System

By applying observability best practices to our delivery infrastructure, we gain instantaneous visibility into execution health:

  • Distributed Tracing for Builds: Modeling each pipeline stage, container initialization, and test runner as spans in an OpenTelemetry trace.
  • Automated Failure Fingerprinting: Parsing failure traces to automatically categorize flaky tests, environment timeouts, or genuine code regressions.
  • Real-Time Notification Flows: Routing rich context notifications directly to engineering channels so teams can remediate issues before blocking releases.
# OpenTelemetry trace instrumentation snippet for pipeline steps
- name: Run Test Suite with Telemetry
  env:
    OTEL_EXPORTER_OTLP_ENDPOINT: "http://collector:4317"
    OTEL_SERVICE_NAME: "ci-pipeline-runner"
  run: |
    ./run-tests-with-telemetry.sh

Observability transforms CI/CD from a black box into an intelligent, self-monitoring delivery platform.

Architecting Developer-First AI Platforms & Go CLI Tooling

Building automated workflows for validating, versioning, and publishing reusable AI agents and skills.

Read Full Article ▼

Moving Beyond Ad-Hoc Prompts

As AI capabilities integrate deeper into engineering workflows, managing agent configurations, custom skills, and prompt templates in unstructured files quickly becomes unmaintainable.

To scale AI tools across teams, we need developer platforms that treat AI resources with the same rigor as production code:

  • Declarative Schemas: Defining AI agent capabilities, allowed tool groups, and system prompts in validated YAML/JSON specifications.
  • Automated CI Validation: Running automated verification pipelines to lint prompt schemas, check model version compatibility, and run regression evals on every commit.
  • Go-Based Developer CLI: Providing engineers with a blazing-fast, cross-platform CLI tool for scaffolding, testing, and publishing agents to a central registry.
# Example CLI command for validating and publishing an AI skill
$ ai-platform skill validate ./skills/code-review
✔ Schema valid
✔ 12 test evaluations passed
$ ai-platform skill publish ./skills/code-review --version v1.2.0
